# ระบบจองห้อง GEWERTZ SQUARE

ระบบจองห้องประชุม/อบรม สำหรับพื้นที่ Gewertz Square (GWSQ) ภาควิศวกรรมไฟฟ้า คณะวิศวกรรมศาสตร์ จุฬาลงกรณ์มหาวิทยาลัย

จองได้ 5 ห้อง — Spark 1, Spark 2, Spark 3, E-III และ Demo Floor
จองเป็นรายชั่วโมง เวลาเปิด 08:00–20:00 น. Spark 1–3 จองแยกห้องหรือรวมทั้ง 3 ห้องในรายการเดียวก็ได้

## สิ่งที่ระบบทำได้

- ผู้ใช้ต้องสมัคร/เข้าสู่ระบบก่อนจอง ทุกคนที่มีบัญชีจองได้
- ทุกใบจองต้องรอผู้ดูแลระบบอนุมัติ และต้องแนบหลักฐานการโอนเงินก่อน (ยกเว้นหน่วยงานภายในที่ใช้ฟรี)
- คำนวณค่าใช้จ่ายอัตโนมัติตามอัตราในประกาศ แสดงรายละเอียดแยกตามห้องและช่วงเวลา
- ผู้ดูแลระบบตรวจสลิป อนุมัติ/ไม่อนุมัติ แก้ไขอัตราค่าใช้จ่าย และกำหนดสิทธิ์แอดมินได้
- กันการจองซ้ำแน่นอนที่ระดับฐานข้อมูล (ไม่ใช่แค่เช็กหน้าเว็บ) รวมถึงกรณีแอดมินกดอนุมัติซ้ำหรือสองคนกดพร้อมกัน

## เทคโนโลยี

| ส่วน | ใช้อะไร | หมายเหตุ |
|---|---|---|
| หน้าเว็บ | Vite + React 19 + TypeScript + Tailwind v4 | สร้างเป็นไฟล์ static ธรรมดา |
| API | Cloudflare Worker (Hono) | เสิร์ฟทั้งหน้าเว็บและ API จากโปรเจกต์เดียว |
| ฐานข้อมูล | Cloudflare D1 (SQLite) | ฟรี 5 GB ไม่ต้องใส่บัตรเครดิต |
| ไฟล์สลิป | เก็บใน D1 (คอลัมน์ BLOB) | บีบอัดรูปฝั่งเบราว์เซอร์ก่อนอัปโหลด ไม่ต้องใช้ R2 ที่ต้องผูกบัตร |
| ระบบล็อกอิน | email + password (PBKDF2) + session cookie แบบ HttpOnly | ไม่พึ่งผู้ให้บริการภายนอก |

ทั้งระบบอยู่ใน **free tier ของ Cloudflare ที่ไม่ต้องผูกบัตรเครดิต** และมี URL ใช้งานได้ทันทีที่ `*.workers.dev` โดยไม่ต้องซื้อโดเมน

## อัตราค่าใช้จ่าย

อัตราอ้างอิงจากประกาศ "เกณฑ์การใช้และอัตราค่าใช้พื้น Gewertz Square" (มีผล 28 สิงหาคม 2569) — บันทึกไว้ในตาราง `rate_cards` และแก้ไขได้จากหน้าผู้ดูแลระบบ

ประกาศกำหนด "เต็มวัน" = 08:00–16:00 (8 ชม.) และ "ครึ่งวัน" = 4 ชม. ระบบนี้จึงคิดเป็นรายชั่วโมง โดยเอาอัตราครึ่งวันหาร 4 ซึ่งให้ผลตรงกับราคาที่ประกาศกำหนดทุกกรณี

| ช่วงเวลา | หน่วยงานภายใน | ร่วมกับหน่วยงานภายใน | หน่วยงานภายนอก |
|---|---|---|---|
| 08:00–16:00 | ฟรี | 375 บาท/ชม. | 750 บาท/ชม. |
| หลัง 16:00 | ฟรี | 500 บาท/ชม. | 550 บาท/ชม. |

อัตราเดียวกันทุกห้อง (Spark 1–3, E-III, Demo Floor) — เอกสารไม่ได้แยกอัตราตามห้อง

ตัวอย่าง: จอง Spark 1–3 รวม เวลา 13:00–18:00 ประเภทหน่วยงานภายนอก
= 3 ห้อง × (3 ชม. × 750 + 2 ชม. × 550) = 3 × 3,350 = **10,050 บาท**

ผู้จองต้องเลือกประเภทผู้ใช้เองตอนกรอก ผู้ดูแลระบบเป็นผู้ตรวจสอบความถูกต้อง

## ขั้นตอนการใช้งานของผู้ใช้

1. สมัครหรือเข้าสู่ระบบ
2. เลือกวันที่ เลือกช่วงเวลา และเลือกห้อง (หรือเลือก Spark 1–3 พร้อมกัน)
3. กรอกประเภทผู้ใช้ จำนวนผู้เข้าใช้ และวัตถุประสงค์ พร้อมดูยอดค่าใช้จ่ายก่อนยืนยัน
4. **หน่วยงานภายใน (ค่าใช้จ่าย 0 บาท):** ระบบอนุมัติให้ทันที ไม่ต้องรอแอดมิน ถ้าช่วงเวลาว่างอยู่จริง — ถ้าไม่ว่างระบบจะไม่ให้จองทับตั้งแต่ต้น
5. **กิจกรรมที่มีค่าใช้จ่าย:** โอนเงินตามจำนวนที่ระบบคำนวณ แล้วแนบสลิปที่หน้า "การจองของฉัน" จากนั้นผู้ดูแลระบบตรวจสลิปแล้วจึงอนุมัติ

### กติกาการถือช่วงเวลา

- รายการ **รอชำระเงิน** ถือช่วงเวลาไว้ **24 ชั่วโมง** แล้วปล่อยให้จองได้อีก — กันไว้ก่อนเพราะคนที่โอนเงินแล้วต้องได้ห้องแน่นอน
- ผู้ใช้ยกเลิกเองได้ทั้งรายการที่ยังรอชำระเงิน และรายการที่อนุมัติแล้วแต่ไม่มีค่าใช้จ่าย
- รายการที่อนุมัติแล้วและ**มีค่าใช้จ่าย** ยกเลิกเองไม่ได้ ต้องให้ผู้ดูแลระบบจัดการเรื่องคืนเงิน

## รันบนเครื่องตัวเอง

```bash
npm install
cp .dev.vars.example .dev.vars   # ใส่ SESSION_SECRET และ ADMIN_EMAILS
npm run db:migrate              # สร้างตารางใน D1 บนเครื่อง
npm run dev:api                 # API ที่ :8787
npm run dev                     # หน้าเว็บที่ :5173 (proxy /api ไปที่ :8787)
```

`ADMIN_EMAILS` คืออีเมลที่ต้องการให้เป็นผู้ดูแลระบบ (คั่นด้วย comma ได้หลายคน) ระบบจะเลื่อนสิทธิ์ให้อัตโนมัติตอนสมัครหรือเข้าสู่ระบบ

## ขึ้นระบบจริงบน Cloudflare (ยังไม่ได้ทำ — ต้องมีบัญชีก่อน)

1. สมัครบัญชี Cloudflare ฟรี (ไม่ต้องใส่บัตร)
2. `npm i -g wrangler && wrangler login`
3. `wrangler d1 create gewertz-booking` แล้วนำค่า `database_id` ที่ได้ไปใส่ใน `wrangler.jsonc`
4. `npx wrangler secret put SESSION_SECRET` (สร้างค่าสุ่มยาว ๆ)
5. แก้ `vars.ADMIN_EMAILS` ใน `wrangler.jsonc` ให้เป็นอีเมลผู้ดูแลจริง
6. `npm run db:migrate:remote`
7. `npm run deploy`

หรือให้ GitHub Actions deploy อัตโนมัติ: ใส่ secrets ชื่อ `CF_API_TOKEN` และ `CF_ACCOUNT_ID` ใน repo แล้ว push ไปที่ branch `main`

> หมายเหตุ: หากใช้ `workers.dev` คุกกี้จะเป็นแบบ HTTPS อัตโนมัติ ถ้าภายหลังต้องการโดเมนของตัวเอง ให้ชี้ CNAME ของโดเมนเข้าหา Worker แล้วตั้ง `secure` ของคุกกี้เป็น `true` คงที่
